---
name: publish-latest-desktop
description: 按一个或多个 CPU 架构发布当前系统的桌面安装包和升级包，自动读取各自历史版本或使用用户指定的下次版本号。
---

当用户要求发布最新安装包和升级包时，调用 publish_latest_desktop_packages 一次，不要运行终端命令或自行猜测版本、平台和路径。
只有用户明确指定下次版本号时才传入 nextVersion，否则传空字符串。将用户指定的全部架构放在一次调用的 architecture 中，以逗号分隔；arm 表示 arm64，例如 "arm64,x64"。未指定架构时传空字符串，使用手工打包页面所选架构。
工具使用打包配置中的源码目录和输出目录，分别读取各架构历史增量包的目标版本作为当前版本，自动计算下次版本；没有历史包时使用 1.0.0 和 1.0.1。显式指定的下次版本用于所有架构。
每个架构需分别审批；全部批准后按指定顺序串行执行。如有拒绝则整个批次不执行，任何架构失败时停止后续架构并报告已完成项。不要拆成多个调用或并发打包。
默认 downloadOpenClaw=false、downloadNodeModules=false：对应缓存存在时直接使用，缓存不存在时自动下载，不再询问。仅当用户明确要求下载某一项时才将该项设为 true，此时无论缓存是否存在都会下载；要求下载两项时分别设为 true，不要把“发布最新安装包”理解为要求重新下载依赖。下载失败应报告错误。
执行前需要启用跨平台任务插件权限并审批；使用升级打包配置中保存的源码目录、输出目录和升级地址，以及与手工打包相同的内置脚本。Native AOT 和 macOS 签名、公证设置使用手工打包页面当前值。此技能按用户要求发布升级包和安装包，不受手工页面发布类型选择影响。
仅支持当前系统脚本支持的架构：Windows 目前只支持 x64，Linux 和 macOS 支持 x64、arm64；不支持的架构会在打包前报错。跨 CPU 架构的 Native AOT 发布还需要目标架构的编译工具链和依赖，不能保证每台机器都能成功。下次版本必须大于各架构的当前版本，次版本号和修订号均为 0 至 99。只根据工具返回结果报告成功或失败，不要重复启动发布。
发布失败后，优先使用工具结果中的本地诊断信号；后续用户要求排查时调用 read_last_packaging_failure。诊断信号只是线索，不足以确认根因时，请用户查看任务日志并提供脱敏的错误，不要扫描整个工作区、猜测问题或自动重新打包。原始日志保留在本地，不会自动发送给模型。
